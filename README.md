# Nacos 跨集群同步客户端最终方案

## 1. 项目说明

开发一款 Windows、Mac 双平台桌面客户端，用于两个 Nacos 集群之间的配置同步。

本工具只同步 Nacos 配置，不同步服务实例、注册信息、服务发现数据。

软件定位为简洁运维工具，界面清晰、操作直接，不增加无关功能。

## 2. 技术方案

最终方案选择：Electron + Vue 3。

### 2.1 方案 A：Electron + Vue 3

推荐作为最终实现方案。

优点：

- 开发速度快。
- Windows、Mac 双平台 UI 一致。
- 前端表格、弹窗、日志窗口、筛选列表实现方便。
- Nacos 接口调试、YAML/JSON 解析、Key 扫描逻辑更容易维护。
- 后期修改同步逻辑时，只需要维护一套代码。

缺点：

- 安装包偏大。
- 内存占用高于原生应用。

结论：

本项目是运维配置同步工具，不是高性能大型软件。核心诉求是开发快、双平台一致、逻辑易维护、后期好改，因此 Electron + Vue 3 是最合适方案。

### 2.2 方案 B：原生开发

Windows 使用 C# WinForm/WPF，Mac 使用 Swift。

不推荐。

主要原因：

- Windows、Mac 两套代码。
- UI 不一致。
- 同步逻辑、Nacos 请求、配置解析、弹窗交互都要写两遍。
- 后期维护成本高，修改一个同步规则需要两端分别修改和测试。

### 2.3 方案 C：Qt

不作为首选。

Qt 性能较好、包体较小，但 UI 开发体验和现代前端相比不够顺手。本项目大量依赖列表、表格、Key 扫描结果、弹窗确认、日志窗口等交互，Electron + Vue 3 更适合。

## 3. 连接配置规则

连接配置字段严格固定，不增加额外字段。

### 3.1 源 Nacos

填写字段：

- 地址
- 账号
- 密码

连接成功后自动拉取全部 Namespace，并通过下拉框选择。

源 Namespace 禁止手动输入。

源 Nacos 只读，作为数据来源，程序绝不修改源 Nacos 的任何数据。

### 3.2 目标 Nacos

填写字段：

- 地址
- 账号
- 密码

连接成功后：

- 自动拉取目标所有已存在 Namespace。
- Namespace 通过下拉框选择，禁止手动输入。
- 下拉框右侧提供新增按钮。
- 点击新增按钮后弹窗输入 Namespace ID 和描述。
- 创建成功后自动刷新目标 Namespace 下拉框，并默认选中新建的 Namespace。

## 4. 同步等级

同步等级固定为三级，不增减：

- Namespace 级别
- 文件级别
- Key 级别

同步优先级：

Namespace 级别 > 文件级别 > Key 级别。

### 4.1 Namespace 级别同步

流程：

- 用户选择源 Namespace 和目标 Namespace。
- 一次性同步源 Namespace 下全部配置文件。
- 目标不存在文件时，直接新建。
- 目标已存在文件时，必须进行双重确认后才允许覆盖。

Namespace 级别同步双重确认规则：

- 第一次确认：提示本次将同步整个源 Namespace 下的全部配置文件，并展示预计影响的文件数量。
- 第二次确认：当目标存在同名 DataId + Group 时，再次提示这些文件将被覆盖，用户必须确认后才执行覆盖。
- 任意一次确认选择取消或跳过，都不得执行对应覆盖操作。
- 仅目标不存在的文件，在用户确认开始 Namespace 同步后可以直接创建。

### 4.2 文件级别同步

流程：

- 源区域展示当前 Namespace 下所有配置列表。
- 支持单选、多选配置文件。
- 同步至目标选中的 Namespace。
- 目标不存在该文件时，直接创建完整配置。
- 目标已存在该文件时，弹窗确认是否覆盖。

### 4.3 Key 级别同步

Key 级别同步是核心功能，必须严格实现。

流程：

- 用户输入 Key 名称。
- 点击扫描。
- 程序在当前源 Namespace 内所有配置文件中检索包含该 Key 的文件。
- 列表展示文件名、分组、Key 路径、原值。
- 支持多选扫描结果。
- 每一条扫描结果都允许用户选择同步方式。

每条扫描结果支持两种同步方式：

- 仅同步当前 Key：只新增或更新这一个 Key，不修改文件其他内容。
- 同步该 Key 所在完整文件：直接覆盖整个配置文件。

## 5. 文件存在性判断逻辑

判断维度固定为目标 Namespace 下是否存在同一个 DataId + Group。

### 5.1 目标不存在配置文件

弹窗提示：

目标不存在此配置文件。

可选操作：

- 确认创建文件并同步。
- 跳过本条。

### 5.2 目标存在文件，但没有当前 Key

自动追加该 Key 到目标文件末尾。

### 5.3 目标存在文件且存在当前 Key

弹窗提示是否覆盖当前 Key 值。

可选操作：

- 覆盖。
- 跳过。

## 6. 界面布局

界面布局固定，保持简洁运维工具风格。

### 6.1 左侧：源 Nacos 区域

包含：

- 地址输入框
- 账号输入框
- 密码输入框
- 连接测试按钮
- Namespace 下拉框，只读，不可手动输入
- 同步等级单选框：Namespace / 文件 / Key

### 6.2 右侧：目标 Nacos 区域

包含：

- 地址输入框
- 账号输入框
- 密码输入框
- 连接测试按钮
- Namespace 下拉框，只读，不可手动输入
- 新建 Namespace 按钮

### 6.3 中间区域

用于展示当前同步等级对应的数据列表。

展示内容：

- 文件级别：配置文件列表。
- Key 级别：Key 扫描结果列表。

列表必须支持多选。

### 6.4 底部区域

实时日志窗口。

日志内容包括：

- 连接结果
- Namespace 拉取结果
- 文件扫描过程
- Key 扫描过程
- 同步操作记录
- 覆盖、跳过、创建等用户操作
- 错误信息

## 7. 日志与本地数据

### 7.1 日志目录选择

应用必须支持用户选择日志文件存储位置。

Windows 规则：

- 安装过程中提供日志存储路径选择。
- 默认优先使用 `D:\NacosSyncTool\logs`。
- 如果当前机器不存在 D 盘，则使用应用默认数据目录。
- 用户可以在安装时改为其他目录。

Mac 规则：

- 首次启动时弹出日志目录选择。
- 用户可以选择任意有写入权限的目录。
- 如果用户跳过选择，则使用应用默认数据目录。

通用规则：

- 应用内提供日志目录修改入口。
- 应用内提供打开日志目录入口。
- 日志目录变更后，新日志写入新目录，历史日志不自动迁移。
- 如果自定义目录不可写，提示用户重新选择。

### 7.2 日志文件分类

日志文件至少包含：

- 运行日志
- 同步日志
- 错误日志

同步日志需要长期保存到本地，支持在应用内查看和清空。

### 7.3 连接信息存储

连接信息本地加密保存。

保存内容：

- 源 Nacos 地址、账号、密码。
- 目标 Nacos 地址、账号、密码。
- 最近选择的源 Namespace。
- 最近选择的目标 Namespace。
- 自定义日志目录。

## 8. 全局规则

- 源 Nacos 永远只读，不做任何修改。
- 所有覆盖动作必须弹窗确认，禁止静默覆盖。
- Namespace 级别同步属于高风险操作，必须执行双重确认。
- 所有同步记录保存本地，可查看、可清空。
- 连接信息必须本地加密保存。
- 支持 Nacos 1.x、2.x 版本。
- 同步过程中按钮置灰，防止重复点击。
- 网络异常、登录失败、权限不足、Namespace 不存在、配置解析失败时，必须给出明确错误日志。
- 不新增与配置同步无关的功能。

## 9. 交付要求

最终交付内容：

- Windows 便携版可执行文件（免安装，下载后可直接运行）。
- Mac 安装包。
- 完整源代码。
- 可二次迭代的清晰代码结构。

代码要求：

- Electron 主进程、渲染进程职责清晰。
- Nacos API 请求封装独立。
- 同步逻辑独立。
- YAML/JSON/Properties 等配置解析逻辑独立。
- 日志模块独立。
- 本地加密存储模块独立。
- 必要位置补充清晰注释。

## 10. 开发结论

本项目最终选择 Electron + Vue 3。

日志目录选择作为正式需求纳入产品设计：

- Windows 安装时可选择，默认优先 D 盘。
- Mac 首次启动时可选择。
- 应用内可随时修改。

该方案既满足 Windows 用户希望日志放在 D 盘的习惯，也兼顾 Mac 的安装方式，适合双平台统一维护。
